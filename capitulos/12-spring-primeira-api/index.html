01

Framework: a oficina já vem equipada

Facilitar o trabalho não significa decidir tudo por você.

🔧 Montar a oficina ou começar a trabalhar?

Imagine fabricar cada ferramenta antes de consertar uma bicicleta. Uma oficina equipada já oferece a bancada, ferramentas e uma organização de trabalho. Você ainda precisa descobrir o defeito e fazer o conserto.

Um framework oferece uma estrutura reutilizável para construir aplicações. Ele estabelece pontos em que nosso código entra e cuida de tarefas comuns. Uma biblioteca costuma ser chamada por nosso programa; um framework também coordena a execução e chama nosso código. Essa é uma diferença de uso, não uma fronteira absoluta.

☕ Java

A linguagem em que escrevemos classes, métodos e regras.

🌱 Spring

Framework que conecta componentes e oferece recursos para construir aplicações.

🚀 Spring Boot

Facilita a configuração e inicialização de aplicações Spring, inclusive com servidor web embutido.

Ao receber um pedido HTTP de cadastro, o Spring pode converter o JSON em um objeto e chamar nosso método. Mas “o nome do fornecedor não pode estar vazio” é uma regra que vamos escrever. O framework não descobre as necessidades do GestorPRO sozinho.

Siga o guia oficial para Linux e a página da sua distribuição. Verifique os requisitos de virtualização. Se você já usa Docker Engine, combine com o professor qual ambiente utilizar: Desktop e Engine podem manter contextos e containers separados.

04

Imagem, container e volume

Três coisas diferentes. Três responsabilidades.

📦 Receita, cozinha funcionando e despensa

A imagem lembra um kit pronto de cozinha. O container é uma cozinha criada com esse kit. O volume lembra uma despensa que continua disponível mesmo quando trocamos aquela cozinha.

Imagem

Pacote com arquivos e configuração para criar containers. Usaremos postgres:17.

Container

Instância isolada criada a partir da imagem. Pode estar executando ou parada.

Volume

Armazenamento gerenciado pelo Docker, separado da vida daquele container.

A analogia tem limite: um container não é um computador completo. Ele executa processos isolados. Docker Desktop pode usar uma máquina virtual para rodar containers Linux no seu sistema.

Colocar o PostgreSQL para funcionar

Um comando de criação; depois, iniciar e parar o mesmo container.

PostgreSQL é o sistema que gerencia nosso banco de dados. Em vez de instalar o servidor diretamente no sistema operacional, vamos usar sua imagem oficial no Docker. Abra o terminal do computador e execute a linha inteira:

Terminal · criar o container uma única vezTerminal
docker run --name gestorpro-postgres -e POSTGRES_DB=gestorpro -e POSTGRES_USER=gestorpro -e POSTGRES_PASSWORD=gestorpro_local -p 127.0.0.1:5432:5432 -v gestorpro-pgdata:/var/lib/postgresql/data -d postgres:17
Leia as opções como uma ficha de configuração
ParteSignificado
--nameNome para localizar nosso container.
-e POSTGRES_...Variáveis que definem banco, usuário e senha na primeira inicialização.
-p 127.0.0.1:5432:5432Expõe a porta no próprio computador. Primeiro 5432: computador; segundo: container.
-v gestorpro-pgdata:...Conecta um volume nomeado à pasta em que esta imagem guarda os dados.
-dExecuta em segundo plano, devolvendo o terminal.
postgres:17Imagem e versão principal usadas na aula.

O primeiro uso pode baixar a imagem. Ao concluir, o comando mostra um identificador longo. No Docker Desktop, abra Containers e localize gestorpro-postgres. O banco ainda pode levar alguns segundos para ficar pronto.

Terminal · conferir o serviçoTerminal
docker ps
docker logs gestorpro-postgres
docker exec gestorpro-postgres pg_isready -U gestorpro -d gestorpro

Na última verificação, procure accepting connections: o servidor está aceitando conexões. docker exec executa um comando dentro de um container em execução.

🐛 Porta ocupada, nome repetido ou senha errada?
  • Porta 5432 ocupada: combine uma porta livre, como 5433. Troque somente a primeira porta em 127.0.0.1:5433:5432 e depois use 5433 na URL JDBC.
  • Nome já existe: confira docker ps -a. Se for seu container desta aula, use docker start gestorpro-postgres.
  • Senha mudou no comando, mas não no banco: as variáveis inicializam um volume vazio. Elas não redefinem a senha de um banco já existente. Use a credencial original e peça ajuda para recuperá-la, sem apagar o volume.
  • Imagem diferente: este roteiro fixa PostgreSQL 17. A imagem 18 usa outro caminho de volume; não troque a versão sem revisar a configuração.
Senha de laboratório

gestorpro_local é apenas uma credencial didática local, repetida no exemplo de conexão. Não reutilize senhas pessoais aqui.

Terminal · entrar no cliente SQLTerminal

06

SQL: conversar diretamente com o banco

Antes de pedir ao Java, vamos fazer com as próprias mãos.

Uma tabela organiza registros. Cada linha é um fornecedor; cada coluna guarda uma informação, como nome ou telefone. O tipo define quais valores cabem na coluna. A chave primária identifica cada linha sem repetir.

SQL significa Structured Query Language, linguagem de consulta estruturada. Usamos instruções SQL para criar estruturas, consultar e modificar dados. CRUD reúne quatro operações sobre registros: criar, ler, atualizar e excluir.

C INSERT · cadastrarR SELECT · consultarU UPDATE · alterarD DELETE · excluir

1 · Preparar a tabela de treino

Digite no psql. Esta tabela se chama fornecedores_treino; a API usará outra, chamada fornecedores. Assim você poderá revisitar o treino sem misturar os cadastros.

psql · criar a estruturaSQL
-- Execute dentro do psql. A tabela de treino fica separada da API.
CREATE TABLE IF NOT EXISTS fornecedores_treino (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(255) NOT NULL,
    cnpj VARCHAR(255),
    categoria VARCHAR(255),
    telefone VARCHAR(255)
);

BIGINT é um inteiro grande. GENERATED BY DEFAULT AS IDENTITY permite ao banco gerar o ID quando não o informamos. PRIMARY KEY define a chave primária. VARCHAR(255) guarda texto de até 255 caracteres. NOT NULL impede ausência de valor; não impede um texto vazio. IF NOT EXISTS evita recriar uma tabela que já existe.

CNPJ e telefone são texto: têm formatação e não servem para contas. Os CNPJs deste capítulo são dados ilustrativos; não faremos validação de documentos agora. CREATE TABLE cria a estrutura, enquanto o “C” do CRUD de registros é feito por INSERT.

2 · Cadastrar e anotar o ID

psql · INSERTSQL
INSERT INTO fornecedores_treino (nome, cnpj, categoria, telefone)
VALUES ('TechDistrib', '12.345.678/0001-90', 'Eletrônicos', '(83) 3333-1000')
RETURNING id;

Resultado esperado: uma linha criada e um ID devolvido por RETURNING id. Anote o valor: ele não precisa ser 1. As sequências podem ter saltos, e repetir o INSERT cria outra linha.

3 · Consultar todos; depois, apenas um

psql · SELECTSQL
SELECT * FROM fornecedores_treino ORDER BY id;
SELECT * FROM fornecedores_treino WHERE id = 1;

* pede todas as colunas. ORDER BY id ordena a exibição. WHERE filtra: a segunda consulta só devolve a linha cujo ID é 1. Troque 1 pelo ID que você anotou.

4 · Alterar e conferir

psql · UPDATESQL
UPDATE fornecedores_treino SET telefone = '(83) 3333-2000' WHERE id = 1;
SELECT * FROM fornecedores_treino WHERE id = 1;

SET escolhe a coluna e seu novo valor; WHERE escolhe as linhas. Você deve ver UPDATE 1 e depois o novo telefone. UPDATE 0 indica que nenhuma linha foi alterada — confira o ID.

5 · Excluir e conferir a ausência

psql · DELETESQL
DELETE FROM fornecedores_treino WHERE id = 1;
SELECT * FROM fornecedores_treino WHERE id = 1;

O DELETE remove a linha escolhida; não apaga a tabela. Depois da exclusão, o SELECT desse ID deve retornar zero linhas.

Ligar Java e PostgreSQL

A API ainda não tem rotas. Primeiro ela precisa iniciar.

O main continua existindo

Abra o arquivo que o Initializr criou. Assim como no Cap 11, há um ponto de entrada. A diferença é que ele inicia a aplicação Spring:

ApiApplication.java · já gerado pelo InitializrJava
package br.com.gestorpro.api;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class ApiApplication {
    public static void main(String[] args) {
        SpringApplication.run(ApiApplication.class, args);
    }
}

@SpringBootApplication é uma anotação: metadados lidos pelo framework, não um comentário. Ela reúne configurações para inicializar a aplicação e descobrir seus componentes. SpringApplication.run inicia esse processo e o servidor web.

O endereço do banco

Em src/main/resources/application.properties, substitua o conteúdo por:

application.propertiesConfiguração
spring.application.name=api
spring.datasource.url=jdbc:postgresql://localhost:5432/gestorpro
spring.datasource.username=gestorpro
spring.datasource.password=gestorpro_local
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
Por que cada linha existe
PropriedadeFunção
spring.application.nameNome da aplicação.
spring.datasource.urlURL JDBC: protocolo, banco PostgreSQL, computador, porta e nome do banco. JDBC é a API Java para acesso a bancos.
username / passwordAs mesmas credenciais da primeira inicialização do container.
ddl-auto=updateNa aula, permite atualizar a estrutura conforme as entidades. Não substitui um processo de migrações em sistemas reais.
show-sql=trueMostra SQL executado pelo Hibernate no console da API.

Nossa aplicação Java está no computador, então usa localhost. Se você publicou o banco na porta 5433, ajuste essa porta na URL. O PostgreSQL não recebe HTTP: abrir localhost:5432 no navegador não é um teste da conexão.

JPA

Jakarta Persistence: especificação para mapear objetos Java e dados persistentes.

Hibernate

Implementa JPA. Converte operações com entidades em acesso ao banco, produzindo SQL.

Spring Data JPA

Fornece implementações de repositories e métodos prontos para operações comuns.

🐛 A API não iniciou?
  • Connection refused: confira Docker Desktop, container, porta e pg_isready.
  • Password authentication failed: compare usuário e senha com o banco que inicializou o volume.
  • Port 8080 already in use: encerre a execução anterior da sua API na IDE antes de executar outra.
  • Imports não resolvidos: confirme a sincronização do Maven e a conexão para baixar dependências.
  • Failed to configure a DataSource: confira o nome e o local de application.properties. O driver sozinho não informa em qual banco conectar.

Uma responsabilidade por camada

O caminho de um pedido não é a ordem em que criamos os arquivos.

🍽️ Um pedido atravessa o restaurante

O atendimento recebe o pedido, a cozinha organiza sua preparação e alguém consulta o estoque. A ficha do ingrediente descreve seus dados; ela não vai sozinha ao depósito. Na aplicação, também separamos responsabilidades.

🎮 ControllerRecebe HTTP e devolve a resposta
↓
⚙️ ServiceOrganiza a operação e suas regras
↓
🗄️ RepositoryAcessa os dados
↓
🐘 PostgreSQLGuarda os registros
📐 Model · Fornecedor

Representa os dados usados pelas camadas. Não é uma chamada entre Service e Repository.

MVC significa Model–View–Controller. É uma separação entre dados/regras, apresentação e controle de entrada. Não é outro nome para as quatro pastas acima. No nosso sistema, React faz a apresentação; esta API usa @RestController e devolve dados em JSON, em vez de renderizar uma página HTML.

Vamos construir na direção contrária: Model → Repository → Service → Controller. Primeiro precisamos dos dados, depois de quem os acessa, de quem organiza a operação e de quem a oferece pela web.

Quem conecta esses objetos?

No Cap 11, você usava new. Agora o Spring cria e gerencia os componentes identificados por anotações, como @Service e @RestController. Quando uma classe precisa de outra, o Spring fornece essa dependência: isso é injeção de dependência.

Primeiro, o construtor que você já conhece

Para funcionar, o Service precisa de um Repository. Vamos declarar essa necessidade no construtor. Observe o mecanismo; os arquivos completos serão escritos no próximo bloco.

Exemplo conceitual · construtor escrito à mãoJava
@Service
public class FornecedorService {
    private final FornecedorRepository repository;

    public FornecedorService(FornecedorRepository repository) {
        this.repository = repository;
    }
}

O parâmetro recebe o Repository e this.repository = repository guarda essa referência no campo do objeto. final indica que esse campo só recebe sua referência uma vez; isso não torna o objeto Repository imutável. O Spring localiza a dependência e chama esse construtor para criar o Service.

Quando existe um único construtor, o Spring o utiliza sem precisar de @Autowired. A dependência já chega na criação do objeto, em vez de ser preenchida depois em um campo.

Agora, o mesmo construtor gerado pelo Lombok

Exemplo conceitual · mesma dependência, menos escritaJava
@Service
@RequiredArgsConstructor
public class FornecedorService {
    private final FornecedorRepository repository;
}

@RequiredArgsConstructor gera um construtor para os campos final que ainda não receberam valor. Neste exemplo, ele gera justamente o construtor acima. Não mantenha o construtor explícito junto com a anotação: são duas formas de produzir a mesma assinatura.

Lombok gera o construtor; Spring fornece a dependência. No Controller, o mesmo padrão será usado com private final FornecedorService service;. Não criamos o Service manualmente dentro do Controller.

service/FornecedorService.javaJava
package br.com.gestorpro.api.service;

import br.com.gestorpro.api.model.Fornecedor;
import br.com.gestorpro.api.repository.FornecedorRepository;
import lombok.RequiredArgsConstructor;
import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Service;
import org.springframework.web.server.ResponseStatusException;

@Service
@RequiredArgsConstructor
public class FornecedorService {
    private final FornecedorRepository repository;

    public Fornecedor cadastrar(Fornecedor fornecedor) {
        validarNome(fornecedor);
        fornecedor.setId(null);
        return repository.save(fornecedor);
    }

    private void validarNome(Fornecedor fornecedor) {
        if (fornecedor.getNome() == null || fornecedor.getNome().isBlank()) {
            throw new ResponseStatusException(HttpStatus.BAD_REQUEST, "Informe o nome");
        }
    }
}

@Service permite ao Spring descobrir esse componente. @RequiredArgsConstructor gera o construtor que recebe o repository, declarado final. O Spring entrega essa dependência ao criar o Service. validarNome é um método auxiliar privado: será reutilizado na atualização.

isBlank() reconhece texto vazio ou composto apenas por espaços. O operador || significa “ou” e interrompe a avaliação quando a primeira condição já é verdadeira; assim não chamamos um método em null.

Como interromper um cadastro inválido?

throw lança uma exceção e interrompe o fluxo normal do método. ResponseStatusException comunica ao Spring uma falha HTTP. BAD_REQUEST representa 400: o pedido precisa ser corrigido. Essa é uma solução pequena para a aula; não estamos criando um sistema completo de tratamento de erros.

setId(null) garante que o cadastro seja novo, mesmo se alguém enviar um ID no JSON. Depois, save salva e devolve a entidade com o ID gerado. O return leva esse objeto de volta para quem chamou o método.

            throw new ResponseStatusException(HttpStatus.BAD_REQUEST, "Informe o nome");
        }
    }

    public List<Fornecedor> listar() {
        return repository.findAll();
    }

    public Fornecedor buscar(Long id) {
        Optional<Fornecedor> resultado = repository.findById(id);
        if (resultado.isEmpty()) {
            throw new ResponseStatusException(HttpStatus.NOT_FOUND, "Fornecedor não encontrado");
        }
        return resultado.get();
    }

    public Fornecedor atualizar(Long id, Fornecedor dados) {
        Fornecedor existente = buscar(id);
        validarNome(dados);
        existente.setNome(dados.getNome());
        existente.setCnpj(dados.getCnpj());
        existente.setCategoria(dados.getCategoria());
        existente.setTelefone(dados.getTelefone());
        return repository.save(existente);
    }

    public void excluir(Long id) {
        Fornecedor existente = buscar(id);
        repository.delete(existente);
    }
}
