React: o início

No Cap 3 você mexeu na página na mão — createElement, appendChild, pedaço por pedaço. Agora você vai conhecer o React: em vez de dizer o como, você descreve o que a tela deve ser, e ele cuida do resto.

Por que React existe
Da página "na mão" para a página que se descreve sozinha
🛠️ O pedreiro × o arquiteto

No Cap 3 você foi o pedreiro: colocou cada tijolo na mão — "cria o <li>, põe o texto, gruda na lista" — repetindo passo a passo. O React te promove a arquiteto: você entrega a planta ("a tela tem um cabeçalho e uma lista de cards") e ele constrói (e reconstrói, quando os dados mudam) por você.

É a diferença entre programação imperativa (você dá o passo a passo) e declarativa (você descreve o resultado). Veja a mesma ideia dos dois jeitos:

na mão (Cap 3)JavaScript
// você manda cada passo, um por um
const item = document.createElement("li");
item.textContent = "Teclado";
lista.appendChild(item);
com ReactJSX
// você descreve o que quer ver — o React monta
<li>Teclado</li>

💡 E o "SPA"?

React é a peça central de uma SPA (Single Page Application — aplicação de página única). Em vez do navegador recarregar a página inteira a cada clique (a tela pisca em branco), a SPA carrega uma vez e o JavaScript troca só os pedaços que mudam — rápido e fluido, como um app de celular. Sites como Instagram e Gmail são assim.

⚡ O tradutor com motor turbo

Tem um detalhe: o navegador não entende JSX direto (aquele HTML dentro do JS que você vai escrever). Alguém precisa traduzir seu código para JS puro antes. Esse alguém é o Vite — ele traduz na hora, sobe um servidor de desenvolvimento e atualiza a tela sozinho quando você salva (hot reload). É o substituto moderno (e muito mais rápido) do Live Server pra projetos React.

Componentes: a grande ideia do React
Pedaços de tela que você cria uma vez e reusa
🧱 Peças de Lego

Um componente é um pedaço da tela embrulhado num bloco com nome — um Cabecalho, um CartaoProduto, um Rodape. Você monta a peça uma vez e encaixa onde quiser, quantas vezes quiser. A tela inteira vira uma montagem de blocos, igual Lego.

Na prática, um componente é só uma função JavaScript (do Cap 2!) que retorna o pedaço de tela (em JSX). Duas regras de ouro:

  • Nome em Maiúscula (PascalCase): Cabecalho, CartaoProduto. É assim que o React sabe que é um componente seu, e não uma tag HTML comum.
  • Retorna JSX e termina com export default pra outros arquivos poderem usar.
src/Cabecalho.jsxJSX
function Cabecalho() {
  return (
    <header>
      <h1>Minha Loja 🛒</h1>
    </header>
  )
}

export default Cabecalho

Pra usar esse bloco dentro do App, você o importa e o escreve como se fosse uma tag — só que com a inicial maiúscula:

src/App.jsxJSX
import Cabecalho from "./Cabecalho"

function App() {
  return (
    <div>
      <Cabecalho />
    </div>
  )
}

export default App

A tela vira uma árvore de componentes: o App é o tronco, e dentro dele encaixam os blocos. Monte a árvore e passe o mouse para ver cada componente acender no código 👇

return (
<div>

<CartaoProduto />

JSX: HTML morando dentro do JavaScript
Parece HTML, mas tem algumas regrinhas próprias

Aquele HTML que aparece dentro do return tem nome: JSX. É HTML com superpoderes — dá pra injetar JavaScript no meio dele. Mas vem com quatro regrinhas que pegam todo iniciante:

  • 1. Um só elemento "pai". O return precisa devolver um elemento que abraça o resto. Se tiver vários soltos, embrulhe num <div> ou num fragmento vazio <>...</>.
  • 2. É className, não class. Porque class já é palavra reservada do JavaScript.
  • 3. Toda tag fecha. Tags sozinhas precisam da barra: <img />, <br />, <input />.
  • 4. JavaScript vai entre { }. Quer mostrar uma variável ou uma conta no meio do JSX? Põe entre chaves.
src/Cabecalho.jsxJSX
function Cabecalho() {
  const nomeLoja = "Loja do Kelson";

  return (
    <header className="topo">
      <h1>{nomeLoja} 🛒</h1>      {/* JS entre chaves */}
      <p>Temos {2 + 1} categorias</p>
    </header>
  )
}

export default Cabecalho
🧠
Dentro das { } vale qualquer JavaScript que vira um valor: uma variável ({nomeLoja}), uma conta ({2 + 1}), um campo de objeto ({produto.preco}). É a ponte entre a lógica do Cap 2 e a tela.

Props: entregando dados pro componente
O mesmo bloco, com conteúdo diferente cada vez
🎁 A etiqueta da encomenda

Um CartaoProduto vazio não serve de muita coisa — você quer um pra cada produto, cada um com seu nome e preço. As props (de properties, propriedades) são as etiquetas que você cola no bloco ao usá-lo: "este card é o Teclado, R$ 320". O mesmo componente, recheios diferentes.

Lembra que componente é uma função? As props são o argumento que ela recebe (Cap 2!). Você lê as props lá dentro:

src/CartaoProduto.jsxJSX
function CartaoProduto(props) {
  return (
    <div className="cartao">
      <h2>{props.nome}</h2>
      <p>R$ {props.preco}</p>
    </div>
  )
}

export default CartaoProduto

E você passa as props na hora de usar o componente, como se fossem atributos HTML:

src/App.jsxJSX
<CartaoProduto nome="Teclado Mecânico" preco={320} />
<CartaoProduto nome="Monitor 27 pol" preco={1450} />
🔤
Repare: texto vai entre aspas (nome="Teclado"), mas número (ou qualquer JavaScript) vai entre chaves (preco={320}). Se você escrever preco="320", o 320 chega como texto, não como número — e contas quebram depois. O BugZilla adora essa.
✨ Atalho: desestruturar as props

Escrever props.nome, props.preco o tempo todo cansa. Dá pra "abrir" as props já no argumento e usar os nomes direto:

src/CartaoProduto.jsx (versão limpa)JSX
// abre nome e preco direto no argumento
function CartaoProduto({ nome, preco }) {
  return (
    <div className="cartao">
      <h2>{nome}</h2>
      <p>R$ {preco}</p>
    </div>
  )
}

export default CartaoProduto
🔮
Aqui você está repetindo <CartaoProduto /> na mão pra cada produto. E quando os dados vierem numa lista (como o array do Cap 3, no shape da sua API)? No Cap 5 você aprende o .map() — uma linha que gera um card por item automaticamente. Guarde essa vontade. 😉

BugZilla ataca o React!
Os tropeços clássicos do primeiro dia de React
🐛
Bug 1 — escreveu class em vez de className. Costume do HTML puro. O React avisa no console. Conserto: em JSX é sempre className="...".
🐛
Bug 2 — componente em letra minúscula. <cartaoProduto /> o React trata como tag HTML desconhecida e não renderiza. Conserto: componente SEMPRE começa em Maiúscula — <CartaoProduto />.
🐛
Bug 3 — "Adjacent JSX elements must be wrapped...". Você retornou dois elementos soltos. Conserto: embrulhe num <div> ou num fragmento <>...</> — o return só devolve UM pai.
🐛
Bug 4 — número da prop sem chaves. preco="320" manda texto; o certo pra número é preco={320}. E pra mostrar uma variável no JSX, lembre das { } — sem elas, aparece o texto literal props.nome na tela.
👀 Macete de ouro do BugZilla▼
🔦
Tela em branco? Abra o Console (F12) e olhe o terminal do npm run dev — no React, os erros mais úteis aparecem nos dois lugares, com o nome do arquivo e a linha. 90% dos bugs do primeiro dia são uma das quatro coisas acima.

🎯 Tarefa

No topo do App.jsx, crie o array produtos com a cara exata do JSON da sua API do ERP. Por enquanto, ligue um card a cada item na mão (produtos[0], produtos[1]…). No próximo capítulo isso vira uma linha só.

// 👉 mesmo formato do endpoint /produtos do seu backend
const produtos = [
  { id: 1, nome: "Teclado Mecânico", preco: 320 },
  { id: 2, nome: "Monitor 27 pol", preco: 1450 },
];

function App() {
  return (
    <div>
      <Cabecalho />
      <CartaoProduto nome={produtos[0].nome} preco={produtos[0].preco} />
      <CartaoProduto nome={produtos[1].nome} preco={produtos[1].preco} />
    </div>
  )
}

export default App

O que você leva deste capítulo
A fundação de tudo que vem pela frente em React
  • Por que React: você descreve a tela (declarativo) em vez de montá-la passo a passo (imperativo). Base de uma SPA.
  • Vite: cria e roda o projeto (npm create vite@latest → npm run dev), traduz o JSX e recarrega sozinho.
  • Componente: uma função em Maiúscula que retorna JSX, fechada com export default.
  • JSX: um pai só, className (não class), toda tag fecha, e JavaScript entre { }.
  • Props: dados que você passa pro componente como atributos — texto entre " ", número/JS entre { }.
