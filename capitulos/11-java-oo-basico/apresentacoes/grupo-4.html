Grupo 04 · Da escrita ao console

02

“Compilou, então imprimiu.”

Correção: compilar e executar são etapas diferentes.

  • Aspas, parênteses e ; fazem parte da sintaxe da instrução.
  • O compilador gera .class a partir de .java; a JVM executa a partir de main.
  • public permite acesso; static dispensa instância; void não retorna. println precisa executar.
O grupo explica

Que evidência demonstra que a linha chegou de fato ao console?

Apoio para preparar a fala

Sintaxe define a escrita. O compilador traduz fonte .java em bytecode .class; a JVM executa a partir de main. Exemplo: println com texto entre aspas, parênteses e ponto e vírgula. Confira: Depois de executar, o console mostra as linhas na ordem das chamadas. Atenção: Achar que corrigir ou compilar já imprime a mensagem. Limite: public permite acesso; static dispensa instância de Main; void não devolve valor. main chama outros métodos: a execução não fica restrita às linhas escritas nele.

  • Rever Da escrita ao console no capítulo ↗

Grupo 04 · Projeto Java

03

“IntelliJ é o Java.”

Correção: a IDE usa as ferramentas da JDK.

  • O projeto está configurado com JDK 21.
  • Main, Produto e ProdutoService precisam usar o pacote escolhido.
  • HTML: br.com.gestorpro. Projeto já iniciado em org.example pode continuar nele.
O grupo explica

Por que mudar só o package de uma classe pode atrapalhar a montagem?

Apoio para preparar a fala

IntelliJ é a IDE; JDK 21 fornece as ferramentas Java. Pacotes organizam as classes. Exemplo: gestorpro-java, pacote br.com.gestorpro, arquivos Main, Produto e ProdutoService. Confira: SDK 21 configurada e as três classes compilando juntas. Atenção: Confundir a IDE com a linguagem ou mudar o pacote de um único arquivo. Limite: O HTML usa build IntelliJ; quem começou em Maven/org.example mantém seu projeto, com classes em src/main/java/org/example. Maven constrói o projeto e gerencia dependências; pom.xml descreve suas configurações.

Grupo 04 · Tipos e valores

04

“Com aspas dá no mesmo.”

Correção: 12 e "12" têm tipos diferentes.

  • int guarda inteiro; String guarda texto; boolean aceita true ou false.
  • double representa o preço; Long o id. * multiplica e + com String concatena.
  • O compilador rejeita texto em int. double simplifica a aula, com limites para dinheiro real.
O grupo explica

Qual mensagem no código seria texto e qual valor serviria para contar?

Apoio para preparar a fala

O tipo declarado limita os valores aceitos; a conferência ocorre antes de executar. Exemplo: String nome; double preco; int estoque; boolean removeu; Long id. Confira: 12 é inteiro; "12" é texto. preco * estoque calcula, e + com String concatena. Atenção: Usar texto entre aspas em uma variável int. Limite: double simplifica a aula; dinheiro real pede tratamento adequado, como BigDecimal na evolução. Long permite null antes do cadastro; o contador long começa em 1.

Grupo 04 · Decisão e limite

05

“Com cinco ainda repõe.”

Correção: o alerta usa menor que 5, sem incluir o 5.

  • Caderno a 15.0 com estoque 3: total 45.0 e alerta.
  • Com estoque 5: total 75.0 e nenhuma mensagem de reposição.
  • O if só imprime o aviso; nenhuma quantidade é acrescentada.
O grupo explica

Qual mudança na condição incluiria exatamente a fronteira 5?

Apoio para preparar a fala

if executa seu bloco quando a expressão booleana é verdadeira. Exemplo: Caderno: preço 15.0 e estoque 3 produzem 45.0 e o alerta de reposição. Confira: Com estoque 5, total 75.0 e nenhum alerta: 5 < 5 é falso. Atenção: Trocar menor que por menor ou igual sem perceber a mudança da regra. Limite: O alerta só imprime: ele não repõe unidades.

Grupo 04 · Repetição com contador

06

“O for sempre roda uma vez.”

Correção: a condição pode ser falsa logo na entrada.

  • Para etiquetas, i começa em 1 e avança com i++.
  • i <= quantidade inclui a última: com 4, imprime 1, 2, 3 e 4.
  • Com quantidade 0, não imprime; usar < no lugar de <= perde a última etiqueta.
O grupo explica

Como prever a saída sem executar o programa?

Apoio para preparar a fala

for reúne início, condição e atualização para repetir um bloco. Exemplo: Etiquetas de 1 até quantidade, com i <= quantidade e i++. Confira: Quantidade 4 imprime 1, 2, 3, 4; quantidade 0 não imprime. Atenção: Usar i < quantidade e perder a última etiqueta. Limite: A condição é testada antes de cada volta. i++ aumenta i em um após o corpo.

  • Rever Repetição com contador no capítulo ↗

Grupo 04 · Classe e instâncias

07

“Mesmo molde, mesmo estoque.”

Correção: cada new cria uma instância independente.

  • A classe descreve campos e métodos; o objeto guarda seu estado.
  • Monitor tem 1 unidade; Cabo tem 8.
  • Alterar o monitor para 4 mantém o cabo com 8; o setter não cria outro Produto.
O grupo explica

Se os nomes dos produtos fossem iguais, a conclusão mudaria?

Apoio para preparar a fala

Classe define campos e métodos; cada new cria uma instância com estado próprio. Exemplo: Monitor (800.0, 1) e Cabo (20.0, 8); mudar estoque do monitor para 4. Confira: Getters mostram 4 e 8, respectivamente. Atenção: Achar que objetos do mesmo molde compartilham automaticamente o estado. Limite: Até objetos com campos iguais podem ser instâncias diferentes. Getter e setter não criam Produto novo.

  • Rever Classe e instâncias no capítulo ↗

Grupo 04 · Referências compartilhadas

08

“Outra variável é uma cópia.”

Correção: atribuir uma referência pode compartilhar o objeto.

  • Dois new criam A e B; apelido = primeiro também alcança A.
  • Estoque 8 por apelido aparece em primeiro; B continua com 2.
  • apelido = outro só redireciona. Depois, estoque 9 por apelido muda B; A fica 8.
O grupo explica

Qual instrução cria objeto e qual apenas troca um caminho?

Apoio para preparar a fala

A variável de objeto guarda referência. Uma atribuição pode copiar esse caminho sem criar um objeto. Exemplo: primeiro e outro são dois Fones; apelido = primeiro compartilha A; depois apelido = outro aponta para B. Confira: Após estoque 8 por apelido, primeiro lê 8 e outro 2; reatribuir apelido não muda esses campos. Atenção: Achar que cada variável contém uma cópia completa do Produto. Limite: Depois de reatribuir, setEstoque(9) por apelido altera B: primeiro 8, outro 9. A e B no desenho não são endereços físicos.

  • Rever Referências compartilhadas no capítulo ↗

Grupo 04 · Construtor e this

09

“O construtor usa o setter.”

Correção: este construtor faz atribuições diretas.

  • Produto recebe nome, preço e estoque; id começa null.
  • this.preco identifica o campo; preco é o parâmetro atribuído a ele.
  • Construtor tem o nome da classe e não declara retorno, nem void; aqui não valida negativos.
O grupo explica

Que teste revelaria a diferença entre criar com negativo e alterar pelo setter?

Apoio para preparar a fala

O construtor inicializa o objeto; tem o nome da classe e não declara retorno, nem void. this indica o objeto atual. Exemplo: Produto("Fone", 80.0, 2) recebe nome, preço e estoque; this.preco = preco guarda o parâmetro no campo. Confira: Neste modelo, id fica null até cadastrar e os outros campos recebem diretamente os argumentos. Atenção: Achar que this valida ou que o construtor chama automaticamente os setters. Limite: O construtor do HTML não valida negativos. Se o projeto anterior usa id e quatro argumentos, a migração para três deve remover o parâmetro id e ajustar as chamadas quando o Service assumir os ids.

  • Rever Construtor e this no capítulo ↗

Grupo 04 · Acesso e validação

10

“private rejeita negativos.”

Correção: private controla acesso; o if valida o número.

  • Pelo Main, acesso direto a preco não compila. O setter public é uma entrada permitida.
  • Fone com 80.0 recusa -10.0 e aceita 90.0; a regra precisa ser escrita.
  • Caneta com 6 recusa -1 e aceita 0. Isso não protege o construtor sem validação.
O grupo explica

Por que um setter apenas gerado na IDE pode aceitar o valor inválido?

Apoio para preparar a fala

private restringe acesso direto; public permite usar métodos; o if escrito no setter aplica a regra do valor. Exemplo: Fone com 80.0 recusa -10.0 e aceita 90.0; Caneta com 6 recusa -1 e aceita 0. Confira: Preço inválido, 80.0, 90.0; estoque inválido, 6, 0. Acesso direto ao campo privado pelo Main não compila. Atenção: Supor que um setter gerado pela IDE já valida, ou que private impede negativos no construtor. Limite: Validação aqui só está nos setters de preço e estoque; nome/id e construção não têm a mesma regra. Rejeitar antes de atribuir preserva o estado anterior.

  • Rever Acesso e validação no capítulo ↗

Grupo 04 · Entrada e retorno

11

“return escreve na tela.”

Correção: return devolve; println imprime.

  • No extra subtotal(3), 3 é argumento e quantidade é parâmetro.
  • Com preço 80.0, volta 240.0; com 4, volta 320.0. Estoque fica 2.
  • Guardar o retorno não imprime. void admite return sem valor; calcular não é vender.
O grupo explica

Que instrução falta para mostrar o subtotal já guardado?

Apoio para preparar a fala

Argumento é o valor enviado; parâmetro o recebe. return entrega o resultado; println imprime. Métodos também podem calcular. Exemplo: No método extra subtotal(int quantidade), preço 80.0 vezes 3 devolve 240.0; vezes 4 devolve 320.0. Confira: Guardar o resultado não imprime; estoque continua 2. valorEmEstoque, outro extra, calcula preço vezes estoque: 90.0 × 2 = 180.0. Atenção: Confundir quantidade pedida com estoque ou retorno com impressão. Limite: subtotal e valorEmEstoque são ampliações da oficina, ausentes do Produto base. Não vendem, não reservam e não verificam disponibilidade. void admite return; sem valor para encerrar.

  • Rever Entrada e retorno no capítulo ↗

Grupo 04 · Representação textual

12

“Produto@… é o endereço.”

Correção: a representação padrão não expõe endereço físico.

  • Nosso toString devolve uma descrição personalizada; println exibe.
  • Teclado Mecânico pode mostrar id 1, preço 320.0 e estoque 12.
  • @Override substitui o método herdado. Imprimir não salva nem cadastra o objeto.
O grupo explica

Por que um texto legível ajuda a revisar, mas não serve como banco?

Apoio para preparar a fala

toString devolve uma descrição textual; println é quem a exibe. Exemplo: Produto cadastrado: #1 Teclado Mecânico - R$ 320.0 (estoque: 12). Confira: O texto personalizado mostra campos do objeto atual; @Override marca a substituição do método herdado. Atenção: Achar que imprimir Produto salva o cadastro ou revela endereço físico da memória. Limite: Texto não é persistência. A representação padrão com @ e hash não é um endereço físico para inspecionar.

  • Rever Representação textual no capítulo ↗

Grupo 04 · Responsabilidades

13

“Service só existe com Spring.”

Correção: ProdutoService já funciona como classe Java comum.

  • Produto cuida do item; Service reúne operações do cadastro.
  • Main cria, chama e mostra os resultados.
  • Um novo Service tem outra lista e contador; não consulta a instância anterior.
O grupo explica

Em qual classe vocês procurariam a regra de remover um cadastro?

Apoio para preparar a fala

Produto cuida do estado de um item; ProdutoService organiza o cadastro; Main cria, chama e mostra resultados. Exemplo: Main cria um Service e pede cadastrar, listar, buscar e remover. Confira: As três classes funcionam como Java comum, sem anotações Spring. Atenção: Concentrar todas as operações no construtor de Produto ou achar que Service já exige Spring. Limite: Sem construtor declarado nesta classe simples, ProdutoService recebe construtor padrão sem argumentos. Cada new ProdutoService tem lista e contador próprios.

Grupo 04 · Coleção em memória

14

“final congela a lista.”

Correção: final fixa a referência do campo, não os elementos.

  • List<Produto> define o tipo; ArrayList implementa a lista de referências.
  • add e remove continuam possíveis; for-each percorre um item por volta.
  • listar devolve a própria coleção, permitindo modificações por quem a recebe.
O grupo explica

Por que uma lista final ainda pode mudar de tamanho?

Apoio para preparar a fala

List<Produto> define o tipo da lista; ArrayList é a implementação escolhida. Os elementos são referências a Produto. Exemplo: for-each recebe uma referência da lista a cada volta. Confira: Adicionar e remover alteram o tamanho; ler a referência permite alcançar o mesmo objeto. Atenção: Interpretar final como coleção imutável ou listar como cópia. Limite: final impede substituir a referência do campo, não modificar a lista. listar devolve a própria lista, que o chamador pode modificar; não há proteção completa.

  • Rever Coleção em memória no capítulo ↗

Grupo 04 · Cadastro e identidade

15

“new já dá um id.”

Correção: neste modelo, o Service atribui o id ao cadastrar.

  • Em Service novo, Livro e Lápis recebem ids 1 e 2.
  • proximoId++ usa o atual e incrementa; add inclui a referência, return a devolve.
  • Id não é posição; o contador é local e o mesmo objeto pode ser recadastrado por engano.
O grupo explica

O que um Produto criado, mas ainda não cadastrado, tem no campo id?

Apoio para preparar a fala

cadastrar atribui id, adiciona a referência e devolve o Produto. Exemplo: proximoId começa em 1; setId(proximoId++) usa o atual e só então incrementa. Confira: Livro e Lápis, cadastrados nessa ordem em Service novo, recebem ids 1 e 2. Atenção: Confundir id com posição, achar que new Produto já cadastra ou cadastrar o mesmo objeto duas vezes. Limite: O contador é local a cada Service. Cadastrar não bloqueia recadastro do mesmo objeto: usamos cada objeto novo uma vez.

  • Rever Cadastro e identidade no capítulo ↗

Grupo 04 · Busca e ausência

16

“Toda busca entrega Produto.”

Correção: o contrato também permite retornar null.

  • O for-each procura; equals compara valores Long; 2L usa literal long.
  • Em Pasta e Régua, buscar 99L dá null e remover 99L dá false.
  • Conferir != null antes do getter evita NullPointerException; null não é false.
O grupo explica

Por que o programa não deve chamar getNome logo após qualquer busca?

Apoio para preparar a fala

buscarPorId percorre com for-each e compara valores Long com equals; retorna referência ou null. Exemplo: Buscar 2L encontra o segundo cadastrado; buscar 99L não encontra. Confira: Pasta e Régua continuam na lista; buscar 99L dá null e remover 99L dá false. Atenção: Chamar getNome diretamente no resultado de uma busca sem conferir ausência. Limite: O L indica literal long. == null verifica ausência; para estes Long, equals compara valor. null não é Produto e não equivale a false; usar método nele causa NullPointerException.

  • Rever Busca e ausência no capítulo ↗

Grupo 04 · Atualização pelo objeto

17

“Buscar devolve uma cópia.”

Correção: a busca alcança o mesmo objeto da lista.

  • Oficina: Teclado com 2 unidades, Mouse com 5 e id 2.
  • Após buscar 2L e conferir null, o setter do encontrado muda para 8.
  • mouse também lê 8, teclado lê 2. É o U do CRUD; não precisa recadastrar.
O grupo explica

Que resultado seria diferente se realmente fosse uma cópia independente?

Apoio para preparar a fala

A referência devolvida pela busca alcança o mesmo objeto armazenado na lista. Exemplo: Na oficina: Teclado (100.0, 2), Mouse (50.0, 5), ids 1 e 2; encontrado.setEstoque(8) após conferir null. Confira: mouse.getEstoque() passa a 8; teclado continua com 2. Atenção: Criar cópia ou recadastrar para que a mudança apareça na lista. Limite: O U do CRUD acontece pelo setter após a busca. O Service base não declara atualizar; CRUD significa criar, consultar, atualizar e excluir.

  • Rever Atualização pelo objeto no capítulo ↗

Grupo 04 · Remover e observar

18

“Remover apaga o objeto.”

Correção: sai a referência mantida na lista.

  • Livro e Lápis: remover 1L dá true e deixa só Lápis.
  • Repetir remover 1L dá false: já não há esse cadastro na coleção.
  • Se Main ainda referencia Livro, pode usá-lo; nenhum banco foi alterado.
O grupo explica

O que true prova nessa operação e o que ele não prova?

Apoio para preparar a fala

remover busca, retorna false na ausência ou remove a referência da lista. Exemplo: Livro e Lápis: remover 1L devolve true, e a listagem mantém apenas Lápis. Confira: Repetir remover 1L devolve false; no Main final resta Mouse Gamer, tamanho 1. Atenção: Supor que remover destrói todas as referências ou reinicia os ids. Limite: Se outra variável ainda referencia o objeto retirado, ele continua acessível. Não há exclusão em banco nesta aula.

  • Rever Remover e observar no capítulo ↗

Grupo 04 · Ampliação: contar itens

19

“Estoques 2, 0 e 5 dão 7.”

Correção: a atividade 11 conta produtos, não unidades.

  • Estoque > 0 seleciona dois dos três produtos: resultado 2.
  • O contador parte de 0 e cresce uma vez por item aprovado.
  • return depois do laço permite contar todos; lista vazia devolve 0.
O grupo explica

Que outra pergunta seria respondida pela soma 7?

Apoio para preparar a fala

contarComEstoque usa contador iniciado em zero, for-each e condição estoque > 0. Exemplo: Livro com 2, Pasta com 0, Régua com 5. Confira: Resultado 2, não 7; lista vazia resulta em 0. Atenção: Somar unidades ou devolver o contador dentro do laço. Limite: Método acrescentado na atividade 11, não no Service base. return após o laço permite examinar todos os itens.

Grupo 04 · Ampliação: repor unidades

20

“Zero é sempre permitido.”

Correção: estoque zero e reposição zero têm regras diferentes.

  • Na atividade 12, quantidade <= 0 ou id ausente retorna false.
  • Livro com 2 recebe 3: estoque 5 e true, pela alteração via setter.
  • Pedidos 0, -2 e id 99 não mudam o estado. Estouro de int fica fora do exercício.
O grupo explica

Qual validação pertence ao pedido e qual pertence ao estado do Produto?

Apoio para preparar a fala

repor organiza validação da quantidade, busca e mudança de estoque pelo setter. Exemplo: Livro com 2; repor(1L, 3) devolve true e estoque vira 5. Confira: Repor 0, -2 ou id 99 dá false e não altera estoque 5. Atenção: Confundir estoque zero permitido com uma reposição de zero aceita. Limite: Método da atividade 12. Quantidade deve ser > 0; produto precisa existir. Usamos números pequenos; estouro de int não é tratado.

  • Rever Ampliação: repor unidades no capítulo ↗

Grupo 04 · Limites e próximo capítulo

21

“Rodou de novo, então salvou.”

Correção: o Main pode ter cadastrado tudo novamente.

  • A lista é recriada em cada execução; isso não é persistência.
  • Futuro: Controller recebe HTTP, Service organiza, Repository acessa PostgreSQL.
  • Spring conecta objetos; Cap 12 usa Fornecedor. A API e o banco ainda não existem aqui.
O grupo explica

Como separar repetição do cadastro de recuperação de dados persistidos?

Apoio para preparar a fala

Memória dura nesta execução; persistência permite recuperar dados depois. Spring ajuda a configurar e conectar objetos. Exemplo: Futuro fluxo: Controller recebe HTTP, Service organiza regras, Repository acessa PostgreSQL. Confira: Reiniciar recria a lista; dados só reaparecem se o Main cadastrá-los novamente. Atenção: Achar que a lista é banco ou que @Entity/@Service já estão implementados neste projeto. Limite: É uma prévia. No Cap 12 o caso inicial é Fornecedor (id, nome, cnpj, categoria, telefone), sem DTO ou relacionamentos. Transferimos os conceitos de Produto, sem renomear o caso automaticamente.
