Dados de verdade: useEffect & fetch

Desde o Cap 4 seus produtos moram num const dentro do código. Hoje é o dia da promessa: você vai apagar esse array e buscar tudo de uma API rodando na sua máquina — com o fetch do Cap 3 morando no lugar certo: o useEffect.

A dor: o loop infinito
Por que o fetch NÃO pode ficar solto no componente

Só de olhar, essa tentativa parece certíssima — o fetch do Cap 3, o set do Cap 6, tudo no lugar… né?

src/App.jsx — tentativa ingênua 🙈 (NÃO faça!)JSX
const App = () => {
  const [produtos, setProdutos] = useState([])

  // 💣 fetch SOLTO no corpo do componente
  fetch("http://localhost:3000/produtos")
    .then((res) => res.json())
    .then((dados) => setProdutos(dados))

  return ( /* ...a vitrine... */ )
}

Agora pensa com a lição do Cap 6: o corpo do componente roda a cada foto 📸. Siga a bola de neve:

  • o componente renderiza → o corpo roda → o fetch dispara;
  • a resposta chega → setProdutos(dados) → o React tira nova foto;
  • nova foto = o corpo roda DE NOVO → outro fetch → outro set → outra foto → … ∞ 🔥

💡 O nome do problema (e da solução)

Buscar dados, mudar o título da aba, ligar um timer… são efeitos colaterais: coisas que saem do componente e mexem com o mundo lá fora. Efeito colateral não pode morar no corpo (que roda a cada foto). O React tem um quarto separado pra isso, com campainha própria: o useEffect.

🧬
Anatomia do useEffect — O QUE e QUANDO
A sintaxe que confunde todo mundo, desmontada de vez
⏰ O despertador

Configurar um despertador são sempre duas decisões: O QUE tocar (o alarme, a música) e QUANDO tocar (7h todo dia? só uma vez amanhã?). O useEffect é o despertador do componente — e recebe exatamente essas duas coisas, nessa ordem: a função com O QUE fazer e o array com QUANDO fazer.

useEffect( () => { ...o que fazer... } , [ quando fazer ] )
1º argumento → a FUNÇÃO: o que fazer 2º argumento → o ARRAY: quando fazer useEffect → o despertador do componente

Por que todo mundo se enrola? Porque é parêntese + arrow + chave + vírgula + colchete, tudo na mesma linha. O antídoto é nunca digitar de dentro pra fora. Digite a moldura antes do quadro, sempre na MESMA ordem:

1 useEffect() a moldura do hook
2 useEffect(() => {}) O QUE (a função-recado)
3 useEffect(() => {}, []) a vírgula + o QUANDO
4 useEffect(() => { console.log("montou! 🎉") }, []) só AGORA o corpo
🧠
Mnemônico do capítulo: useEffect(O QUE, QUANDO). Se você se perder no meio dos símbolos, pare, apague e recomece pela moldura. Vale até pra quem já programa há anos — sério. 😅
⌨️
A arrow => de novo (é a função O QUE). Sua IDE pode desenhar ⇒, mas são dois caracteres: = e >. E não confunda os irmãos: { } chaves = corpo da função · [ ] colchetes = array do quando.

Seu primeiro useEffect de verdade — digite junto com o prof (pela receita! 1, 2, 3, 4):

src/App.jsxJSX
import { useState, useEffect } from "react"

const App = () => {

  useEffect(() => {
    console.log("o componente montou! 🎉")
  }, [])

  return ( /* ...a vitrine de sempre... */ )
}

⏰
Os 3 modos do QUANDO
O array de dependências decide quando o despertador toca

O array do QUANDO tem só três configurações. Uma por vez:

modo 1 — SEM array (quase sempre é bug!)JSX
useEffect(() => {
  console.log("rodei!")
})   // sem o 2º argumento → roda a CADA foto 📸📸📸
modo 2 — array VAZIO [] (o modo do fetch!)JSX
useEffect(() => {
  console.log("rodei!")
}, [])   // [] → roda UMA vez, quando o componente NASCE
modo 3 — COM dependências [busca]JSX
useEffect(() => {
  console.log("a busca mudou:", busca)
}, [busca])   // roda ao nascer E sempre que busca mudar
  • Sem array — "toque toda hora": roda em toda renderização. Quase nunca é o que você quer (e com fetch, é o loop 🌀).
  • [] vazio — "toque uma vez, ao ligar": roda só quando o componente monta. É O modo pra buscar dados iniciais.
  • [busca] — "toque quando ISSO mudar": roda ao montar e a cada mudança das dependências listadas.

Descubra a tabela na prática: escolha o modo, provoque o componente e olhe o LED + o console 👇

O momento mágico: apague o const
useState vazio + useEffect com fetch + o .map() de sempre

Chegou a hora. O padrão que conecta tudo que você aprendeu — Cap 3 (fetch), Cap 5 (.map) e Cap 6 (estado) — em três passos:

  • 1. A vitrine nasce vazia: useState([]) — sem dados ainda, mas o .map() de um array vazio só desenha… nada. Sem erro.
  • 2. O useEffect busca: modo [] (uma vez, ao nascer) + o fetch do Cap 3 + setProdutos(dados) no final.
  • 3. O .map() nem percebe: quando o set roda, vem a nova foto 📸 — e a MESMA vitrine desenha os dados que chegaram.
src/App.jsx — o padrão canônico ⭐ (decore este bloco!)JSX
import { useState, useEffect } from "react"

// const produtos = [ {...}, {...}, {...} ]   ⚰️ APAGUE!
// (com carinho — ele te serviu bem desde o Cap 4)

const App = () => {
  const [produtos, setProdutos] = useState([])      // 1. nasce vazio

  useEffect(() => {                                   // 2. busca ao nascer
    fetch("http://localhost:3000/produtos")
      .then((res) => res.json())
      .then((dados) => setProdutos(dados))
  }, [])

  return (
    <div>
      {produtos.map((p) => (                          // 3. o mesmo .map()!
        <CartaoProduto key={p.id} nome={p.nome} preco={p.preco} />
      ))}
    </div>
  )
}
🗣️
Leia em voz alta: "nasce vazio → quando o componente montar, busca na API e guarda no estado → o set avisa o React → a nova foto desenha os cards". São 3 linhas trocadas — e a loja sai do código e entra no mundo real.

🧹 Dois vizinhos que você ainda vai conhecer

1) A faxina: o useEffect aceita um return () => {...} — uma função de limpeza que roda quando o componente sai de cena (útil pra desligar timers, por exemplo). Guarde que existe; usaremos quando precisar. 2) async/await: outro jeito de escrever o fetch, sem .then(). Vamos adotá-lo no Cap 9, junto com o axios e o login. Por enquanto, .then() firme e forte.

BugZilla ataca os efeitos!
Os 5 tropeços clássicos do useEffect + fetch
🐛
Bug 1 — fetch solto no corpo: o loop infinito 🌀 (render → fetch → set → render → …). A aba Network vira uma metralhadora. Conserto: fetch SEMPRE dentro do useEffect(() => {...}, []).
🐛
Bug 2 — esqueceu o array do QUANDO: useEffect(() => {...}) funciona… rodando a cada renderização (o bug silencioso: a loja "funciona" mas busca a API a cada tecla da busca!). Conserto: receita da moldura — a vírgula e o [] fazem parte do molde, não são opcionais.
🐛
Bug 3 — esqueceu o import: "useEffect is not defined". Conserto: os dois juntos na mesma linha: import { useState, useEffect } from "react".
🐛
Bug 4 — esqueceu o res.json(): "meus produtos são uma Response?!" — o .map() quebra na hora ("produtos.map is not a function"). Conserto: o primeiro .then((res) => res.json()) traduz a resposta pra JSON; só o segundo .then recebe os dados. (Igualzinho no Cap 3!)
🐛
Bug 5 — "Failed to fetch": o erro nº 1 da aula ao vivo. Quase sempre significa: o json-server não está rodando (ou parou quando você fechou o terminal). Conserto: olhe o Terminal 2 — tem que estar vivo, mostrando a porta :3000. Teste o endereço direto no navegador antes de culpar o React.
👀 Macete de ouro do BugZilla▼
🔦
Vitrine vazia? Investigue na ordem da viagem: 1) o json-server está de pé? (abra localhost:3000/produtos no navegador) · 2) o fetch está DENTRO do useEffect com []? · 3) tem o res.json()? · 4) o console.log(dados) dentro do último .then mostra o array? Se os 4 passarem, o problema está na vitrine (Cap 5), não nos dados.

  • Efeito colateral (buscar dado, mexer no title, timers) não mora no corpo do componente — o corpo roda a cada foto 📸 (fetch solto = loop 🌀).
  • useEffect(O QUE, QUANDO): a função e o array, sempre nessa ordem — e sempre digitados pela receita da moldura (1 moldura → 2 função → 3 vírgula+array → 4 corpo).
  • Os 3 modos do QUANDO: sem array = toda renderização (quase sempre bug) · [] = uma vez ao nascer (o modo do fetch) · [busca] = quando a dependência mudar.
  • O padrão canônico: useState([]) + fetch no useEffect(..., []) + o .map() de sempre. Três linhas trocadas, loja viva.
  • json-server: npx json-server db.json — sua API de treino em localhost:3000, no shape do ERP que vem aí.
  • Loading & erro: estados carregando/erro + porteiros = a diferença entre site amador e profissional.
