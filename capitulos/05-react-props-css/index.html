Listas com .map() — um card por item
O array vira JSX automaticamente
🏭 A fábrica de carimbos

Você já tem o molde (o componente CartaoProduto) e a lista de pedidos (o array produtos). O .map() é a esteira: ele passa item por item da lista pelo molde e cospe um card pronto pra cada um. 3 produtos? 3 cards. 50 produtos? 50 cards. O mesmo código.

Você já viu o .map() no Cap 2: ele transforma cada item de um array e devolve um array novo. Relembra:

o .map() que você já conhece (Cap 2)JavaScript
const numeros = [1, 2, 3];
const dobros = numeros.map((n) => n * 2);   // [2, 4, 6]
// número entra, número sai
o MESMO .map(), agora em ReactJSX
const cards = produtos.map((p) => <CartaoProduto nome={p.nome} />);
// produto entra, JSX sai

Mesma esteira, molde diferente. No Cap 2 cada item virava um número; agora cada item vira um pedaço de tela. Essa é a única novidade:

⌨️
Volta a aparecer a arrow function (p) => ... do Cap 2. Lembre: a setinha => é o = seguido de >. Sua IDE pode desenhar ⇒, mas você digita os dois caracteres separados.
src/App.jsxJSX
import CartaoProduto from "./CartaoProduto"

const produtos = [
  { id: 1, nome: "Teclado Mecânico", preco: 320 },
  { id: 2, nome: "Monitor 27 pol", preco: 1450 },
  { id: 3, nome: "Cadeira Gamer", preco: 980 },
];

const App = () => {
  return (
    <div>
      {produtos.map((p) => (
        <CartaoProduto key={p.id} nome={p.nome} preco={p.preco} />
      ))}
    </div>
  )
}

export default App
🧠
Leia em voz alta: "para cada produto p da lista, devolva um <CartaoProduto> com os dados dele". O { } em volta do .map() é o de sempre: "aqui dentro tem JavaScript". E note que passamos as props (nome, preco) pegando de cada p.

Veja a esteira rodando: o array entra, e sai um card por item. Aperte + adicionar produto e repare que o código não muda 👇

🔑
A prop key — a etiqueta de cada item
Por que o React pede uma e o que acontece sem ela
🔑 As plaquinhas do guarda-volumes

Quando você renderiza uma lista, o React precisa identificar cada item pra saber quem é quem quando a lista muda (um produto sai, outro entra). A key é a plaquinha de cada card — única e estável. Sem ela, o React se atrapalha e fica lento (e te avisa no console com um aviso amarelo).

  • Use sempre um id único do próprio dado: key={p.id}. É o id que veio do banco/API — perfeito pra isso.
  • A key fica no elemento de fora do .map() (o <CartaoProduto>), não dentro do componente.
  • Evite usar a posição (o índice) como key quando a lista pode mudar de ordem — dá bugs sutis. Prefira o id.
⚠️
"Warning: Each child in a list should have a unique key prop." é o aviso mais comum de quem começa com listas em React. Não é um erro que quebra a tela, mas conserte sempre: adicione key={p.id}. O BugZilla volta nisso.

Veja o guarda-volumes funcionando: cada produto deixou um pertence na plaquinha dele. Remova o primeiro da lista e compare o que acontece com e sem key 👇

✅ com key={p.id}
⚠️ sem key (pela posição)
cada plaquinha guarda o pertence do SEU dono

Imagens em React — onde colocar o arquivo
A pasta public/ × importar de src/assets

Mostrar uma imagem é <img src=... alt=... />, como no HTML. A pergunta é: onde fica o arquivo? Em projeto Vite você tem dois caminhos:

Caminho A — pasta public/JSX
// arquivo em: public/teclado.jpg
// referência pelo caminho absoluto (começa com /)
<img src="/teclado.jpg" alt="Teclado" />
Caminho B — importar de src/assetsJSX
// arquivo em: src/assets/teclado.jpg
import teclado from "./assets/teclado.jpg"

// usa a variável importada entre chaves
<img src={teclado} alt="Teclado" />
💡 Qual usar?

public/ é mais simples e bom para poucas imagens fixas (logo, favicon). importar de src/assets deixa o Vite cuidar do arquivo (otimiza e avisa se você apagar a imagem por engano) — é o preferido pra imagens do seu app. E quando a imagem vier da API (Cap 7), o src será só a URL que veio nos dados: <img src={p.imagem} />.

Escolha onde você colocou o arquivo e veja se o <img> acha a imagem 👇

CSS Modules — estilo que não vaza
Cada componente com seu CSS, sem um bagunçar o outro
🏷️ Nomes que viram únicos sozinhos

Num CSS comum, se dois arquivos têm .cartao, eles colidem — o último a carregar vence e bagunça o outro. O CSS Module resolve isso: você escreve .cartao normal, mas o Vite renomeia pra um nome único nos bastidores (tipo cartao_a1b2). Cada componente fica na sua bolha.

É só seguir duas convenções: o arquivo termina em .module.css e você importa ele como um objeto:

src/CartaoProduto.module.cssCSS
.cartao {
  border: 1px solid #e2e8f0;
  border-radius: 12px;
  padding: 14px;
}
.preco {
  color: #16a34a;
  font-weight: 700;
}
src/CartaoProduto.jsxJSX
import styles from "./CartaoProduto.module.css"

const CartaoProduto = ({ nome, preco }) => {
  return (
    <div className={styles.cartao}>
      <h2>{nome}</h2>
      <p className={styles.preco}>R$ {preco}</p>
    </div>
  )
}

export default CartaoProduto
🔤
Repare na mudança: não é mais className="cartao" (texto), e sim className={styles.cartao} (JavaScript entre chaves — você pega a classe do objeto styles que importou). Esquecer as chaves aqui é tropeço clássico.

🚪 O porteiro da festa

Sua loja mostra tudo, sempre. Mas e um selo 💎 Premium que só aparece nos produtos caros? Um Esgotado só em quem não tem estoque? Você precisa de um porteiro na entrada do JSX: ele olha o dado e decide se aquele pedaço de tela entra ou não entra. E lembra: if solto não pode dentro das { } (regra do Cap 4) — o porteiro tem dois jeitos próprios de trabalhar.

⌨️
Vão aparecer o >= (maior ou igual) e o && (E lógico) do Cap 2. Sua IDE pode desenhar ≥ no lugar de >= — mas são dois caracteres que você digita: > e depois =.

Jeito 1 — o && ("se for verdade, mostra"): o porteiro olha a condição à esquerda; se for verdadeira, deixa entrar o que está à direita. Se for falsa, não mostra nada (nem espaço em branco):

src/CartaoProduto.jsx (dentro do return)JSX
<div className={styles.cartao}>
  <h2>{nome}</h2>
  <p>R$ {preco}</p>
  {preco >= 1000 && <span>💎 Premium</span>}
</div>
🗣️
Leia em voz alta: "se o preço for maior ou igual a 1000, e aí sim, mostre o span". O && é o mesmo "E" do Cap 2 — o React só aproveita um detalhe: quando a esquerda é falsa, o JavaScript nem olha a direita, então nada é desenhado.

Jeito 2 — o ternário ? : ("isto ou aquilo"): quando você quer mostrar uma coisa OU outra (não "mostrar ou nada"), usa a pergunta com duas respostas:

src/CartaoProduto.jsx (dentro do return)JSX
{/* condição ? valor-se-sim : valor-se-não */}
<p>{emEstoque ? "✅ Disponível" : "😢 Esgotado"}</p>
🎨 E dá pra decidir a CLASSE também (olha o CSS Module de novo!)

O ternário devolve um valor — e classe é valor! Então dá pra trocar o visual inteiro do card conforme o dado:

src/CartaoProduto.jsxJSX
<div className={emEstoque ? styles.cartao : styles.esgotado}>

Brinque de porteiro: mude o preço e o estoque e repare qual linha do código acende pra desenhar o card 👇

BugZilla ataca as listas!
Os tropeços de quem está aprendendo .map() e estilo
🐛
Bug 1 — esqueceu a key. "Each child in a list should have a unique key prop." Conserto: ponha key={p.id} no elemento de fora do .map().
🐛
Bug 2 — o .map() não devolve nada. Usando { } com chaves no corpo da função, você precisa do return: p => { return <Card /> }. Sem ele, sai a lista vazia. Macete: use parênteses p => ( <Card /> ) — eles já "retornam" o que está dentro.
🐛
Bug 3 — className="styles.cartao" (com aspas). Aí vira o texto literal "styles.cartao", e o estilo não aplica. Conserto: é JavaScript, então chaves: className={styles.cartao}.
🐛
Bug 4 — imagem não aparece (caminho errado). Em src/assets você precisa importar (import x from "./assets/x.jpg"); só escrever src="./assets/x.jpg" costuma quebrar depois do build. Em public/, o caminho começa na raiz: src="/x.jpg".
🐛
Bug 5 — if dentro das chaves do JSX. { if (preco >= 1000) ... } explode com "Unexpected token": dentro das { } só entra o que vira valor. Conserto: use os porteiros — && (mostrar ou nada) ou o ternário ? : (isto ou aquilo).
👀 Macete de ouro do BugZilla▼
🔦
Lista vazia ou sem estilo? Faça console.log(produtos) (a lista chegou mesmo?) e console.log(styles) (saiu um objeto com suas classes?). E leia o aviso amarelo do console — o da key aponta o caminho. Quase todo bug de lista é uma das quatro coisas acima.

O que você leva deste capítulo
Sua loja já mostra muitos produtos, com estilo
  • .map(): transforma o array em JSX — {produtos.map((p) => <Card ... />)}. Uma linha gera a lista toda.
  • key: a etiqueta única de cada item — key={p.id}, sempre no elemento de fora do .map().
  • Imagens: public/ (caminho "/img.jpg") ou import de src/assets (src={img}).
  • CSS Modules: arquivo .module.css + import styles + className={styles.classe} — estilo que não vaza.
  • Mostrar ou esconder: && (mostrar ou nada) e o ternário ? : (isto ou aquilo) — inclusive pra escolher a classe: className={cond ? styles.a : styles.b}. if solto não entra nas chaves.
