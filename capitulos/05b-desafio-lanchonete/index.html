Desafio 1 — a Lanchonete 🍔
★ guiado · 6 passos até o cardápio — o primeiro voo tem instrutor do lado
👨‍🍳 Cozinhar sem olhar a receita

O primeiro cliente quer um cardápio de lanchonete. É o mesmo prato da Mini-loja dos Caps 4 e 5, com ingredientes novos — por isso este desafio ainda te guia passo a passo. Nos próximos, as rodinhas saem da bicicleta. 😄

★ guiadocomponentesprops.map() + keyimagens

Você vai criar um projeto React novo chamado lanchonete, com:

  • Um Banner com duas imagens — uma vinda da pasta public/ e outra importada de src/assets/ (os dois caminhos do Cap 5).
  • Um Cabecalho dando boas-vindas à lanchonete.
  • Um CartaoLanche que recebe nome, preco e descricao por props.
  • Um array lanches com 4 lanches, virando cards na tela com .map() e key.
  • index.css e App.css completamente vazios — a página fica "crua" de propósito (o visual é bônus).

A estrutura final de pastas — repare na novidade pequena, a pasta src/components/ guardando os componentes (organização de projeto de verdade):

Passo 2 — a faxina (sozinho/a)
App.jsx enxuto + index.css e App.css VAZIOS
★ fácilboilerplateCSS limpo
💡 Dica

O Vite entrega o projeto cheio de exemplo. Sua faxina tem 3 alvos, todos dentro de src/:

1. App.jsx — apague tudo e recrie com o rafce, devolvendo só uma <div> com um <h1> qualquer (pra testar).
2. App.css — abra, selecione tudo (Ctrl/Cmd + A), apague, salve. O arquivo fica vazio.
3. index.css — mesma coisa: conteúdo zero.

É o CSS de exemplo do Vite que deixa o fundo escuro e centraliza tudo — limpando os dois, a página volta a ser uma folha em branco.

⚠️
Apague o conteúdo, não os arquivos! O main.jsx importa o index.css e o App.jsx pode importar o App.css — se o arquivo sumir, o import quebra e a tela fica branca. Vazio ≠ deletado.
🚨
Tenta antes! Se o rafce colocar um import React from 'react' no topo, pode apagar essa linha — o Vite moderno dispensa.
👀 Só clique aqui DEPOIS de tentar — Ver solução▼

Passo 5 — o array e a esteira do .map() (sozinho/a)
4 lanches entram, 4 cards saem — sem copiar e colar
★★ médio.map()key
💡 Dica

No App.jsx, crie (fora do componente) um array lanches com 4 objetos, cada um com id, nome, preco e descricao. Depois apague o card de teste do Passo 4 e gere a lista com lanches.map(...), passando as três props a partir de cada item — e a key={l.id}, senão o React reclama no console!

🚨
Tenta antes! Leia em voz alta: "para cada lanche l da lista, devolva um <CartaoLanche> com os dados dele".
👀 Só clique aqui DEPOIS de tentar — Ver solução▼
src/App.jsxJSX
import Cabecalho from './components/Cabecalho'
import CartaoLanche from './components/CartaoLanche'

const lanches = [
  { id: 1, nome: "X-Burger", preco: 18, descricao: "Pão, carne e queijo" },
  { id: 2, nome: "X-Salada", preco: 22, descricao: "Alface, tomate e maionese da casa" },
  { id: 3, nome: "X-Bacon", preco: 26, descricao: "Bacon crocante em dobro" },
  { id: 4, nome: "Batata Frita", preco: 12, descricao: "Porção média bem sequinha" },
]

const App = () => {
  return (
    <div>
      <Cabecalho />
      <h1>Cardápio:</h1>
      {lanches.map((l) => (
        <CartaoLanche key={l.id} nome={l.nome} preco={l.preco} descricao={l.descricao} />
      ))}
    </div>
  )
}

export default App

Passo 6 — o Banner com as duas imagens (sozinho/a)
Uma da public/, outra importada de src/assets — os dois caminhos do Cap 5
★★★ desafiopublic/import de assets
💡 Dica

Escolha duas imagens (baixe da internet — um hambúrguer, um logo, o que quiser):

1. Salve uma como banner.png dentro de public/ → no JSX ela entra com src="/banner.png" (caminho começando com barra, sem import).
2. Crie a pasta src/assets/ (se o Vite já não criou), salve a outra como logo.png → essa entra com import + src={logo}.

Monte tudo num componente Banner.jsx (em components/!) e use no App acima do Cabecalho. Dê um width nas imagens pra não explodirem a tela.

🧭
Atenção ao caminho do import dentro do Banner.jsx: ele mora em src/components/, e a imagem em src/assets/ — ou seja, o caminho sobe um nível: '../assets/logo.png' (dois pontos = "sai da pasta components").
🚨
Tenta antes! Se a imagem aparecer "quebrada" 🧩, revise: a da public/ usa barra e aspas; a de assets usa import e chaves. Misturou? Não funciona.
👀 Só clique aqui DEPOIS de tentar — Ver solução▼

★★ sozinho/a · cards de filmes + o porteiro && no selo de destaque
🎬 O pedido do cliente

"Tenho um cineminha de bairro, o CineDev. Quero uma página com os filmes em cartaz — título, gênero e nota. Ah, e os filmes muito bem avaliados (nota 9 pra cima) merecem um selo de destaque, tipo ⭐. Os outros, não."

★★ sozinho/aprops.map() + keyporteiro &&

📋 O que entregar — projeto novo cinedev (com faxina!), contendo:

  • Cabecalho com as boas-vindas do cinema (em src/components/, claro).
  • CartaoFilme recebendo titulo, genero e nota por props — título em <h2>, o resto em <p>.
  • Array filmes com 5 filmes (id, titulo, genero, nota) virando cards com .map() + key.
  • A novidade: dentro do card, a linha ⭐ Destaque da crítica aparece só quando nota >= 9. Sem CSS — a página fica crua mesmo.

O resultado esperado — repare: só os filmes com nota alta ganham a estrela 👇

🎬
Mãos à obra — cinedev
O esqueleto é o da lanchonete; a novidade é o porteiro
💡 Dica

Até o .map(), este desafio é a lanchonete com outro tema: projeto → faxina → Cabecalho → CartaoFilme com 3 props → array → esteira. Se fez o Desafio 1, você refaz esse arco em bem menos tempo (e sentir isso é o objetivo!).

A parte nova é o porteiro && da seção 👻 do Cap 5: "se a condição for verdadeira, mostra; senão, nada". A condição aqui é nota >= 9, e o que ele deixa entrar é um <p> com a estrela. Vai dentro do JSX do CartaoFilme, entre chaves.

🚨
Tenta antes! Sem espiar: escreva primeiro a lanchonete de memória com tema de cinema. Só abra o 👀 se travar DEPOIS de consultar os Caps 4 e 5.

Desafio 3 — Estante do Dev 📚
★★ sozinho/a · ternário + CSS Modules + classe condicional
📚 O pedido do cliente

"Empresto muitos livros de programação pros amigos e me perco. Quero a Estante do Dev: cada livro num cartão. Se está comigo, o cartão fica verde com "✅ Disponível na estante"; se está emprestado, fica acinzentado com "❌ Emprestado". Bater o olho e saber."

★★ sozinho/aternário ? :CSS Modulesclasse condicional

📋 O que entregar — projeto novo estante-dev (com faxina!), contendo:

  • Cabecalho + CartaoLivro recebendo titulo, autor e disponivel (um booleano! — e booleano vai entre chaves no array).
  • Array livros com 4 livros, uns com disponivel: true, outros false, virando cards com .map() + key.
  • No texto do card, um ternário decide: "✅ Disponível na estante" ou "❌ Emprestado".
  • Um CartaoLivro.module.css com duas classes (.disponivel verde, .emprestado cinza) — e a className do card escolhida pelo mesmo ternário, como na seção 👻 do Cap 5.

O resultado esperado — agora com CSS, os cartões contam a história sozinhos 👇

📚
Mãos à obra — estante-dev
Um booleano, um ternário, duas classes
💡 Dica

O mesmo disponivel é usado duas vezes dentro do CartaoLivro: uma no texto ({disponivel ? "✅ ..." : "❌ ..."}) e outra na classe (className={disponivel ? styles.disponivel : styles.emprestado}). É a dupla ternário + classe condicional da seção 👻 do Cap 5.

Pro CSS Module, lembra do ritual: arquivo termina em .module.css, entra com import styles from ..., e a classe vira styles.nomeDaClasse. E no array, booleano vai entre chaves: disponivel: true (sem aspas!).

⚠️
disponivel="true" com aspas é TEXTO, e texto não-vazio é sempre "verdadeiro" — todos os cartões ficariam verdes! Booleano de verdade não usa aspas, nem no array nem na prop. (Pegadinha clássica do aspas × chaves.)
🚨
Tenta antes! Monte primeiro tudo SEM cor (texto com ternário funcionando). Depois adicione o module.css. Uma coisa de cada vez!
👀 Só clique aqui DEPOIS de tentar — Ver solução▼

Desafio 5 — GameStore 🎮 (o chefão)
★★★ · TUDO junto: props, map, &&, ternário, classe condicional, CSS Modules e .length
🎮 O pedido do cliente (o mais exigente de todos)

"Minha loja de games precisa de um catálogo caprichado: cards lado a lado, selo de 🔥 PROMOÇÃO nos jogos em oferta, e os esgotados têm que aparecer apagadinhos com "⚫ Esgotado" — mas continuam no catálogo! Ah, e no topo quero ver quantos jogos temos, sem eu precisar contar."

★★★ chefãotudo dos Caps 4-5.length

📋 O que entregar — projeto novo gamestore (com faxina!), contendo:

  • Cabecalho que recebe uma prop total e escreve "🎮 GameStore — X jogos no catálogo". No App, quem passa o valor é total={jogos.length} — o array conta a si mesmo (Cap 2!).
  • Array jogos com 5 jogos: id, nome, preco, promocao (booleano) e emEstoque (booleano).
  • CartaoJogo com as 4 props: nome em <h2>, preço, selo 🔥 PROMOÇÃO! só quando promocao for true (porteiro &&), e 🟢 Em estoque × ⚫ Esgotado no ternário.
  • CartaoJogo.module.css com .normal (borda azul React) e .esgotado (borda cinza + opacity: 0.5) — escolhidas por classe condicional em cima de emEstoque.
  • App.module.css com a .vitrine flex — cards lado a lado, como na DevViagens.

O resultado esperado — repare no contador do topo, no selo 🔥 e nos esgotados apagadinhos 👇

🏆
Mãos à obra — gamestore (o teste de fogo final)
Nada aqui é novo. A dificuldade é juntar tudo — e é isso que dev faz
💡 Dica

O chefão é a soma dos 4 anteriores: o arco da lanchonete + o porteiro do CineDev + o ternário/classe da Estante + a vitrine flex da DevViagens. A única peça "nova" é o contador — e ela tem duas partes: o Cabecalho vira um componente com prop (({ total })), e o App passa total={jogos.length}.

Dentro do CartaoJogo, os dois porteiros convivem numa boa: uma linha com {promocao && ...} e outra com {emEstoque ? ... : ...}. Um mostra-ou-some, o outro escolhe-entre-dois.

Monte em fatias e rode a cada fatia: cards crus → selo 🔥 → ternário do estoque → classes → vitrine → contador. Seis saves, seis vitórias.

🚨
Esse é O desafio. Se você entregar a GameStore sem abrir o 👀, pode se considerar oficialmente pronto(a) pro useState do Cap 6. Vai com calma, uma fatia por vez — e boa sorte, dev! 🎮
