Navegação: sua loja vira um site de verdade

Sua loja busca dados da API, trata erro, filtra… mas mora numa página só. Hoje ela ganha endereços: uma página inicial, uma página "sobre" e uma página de detalhes pra cada produto — tudo com o React Router, sem nunca recarregar a tela.

🗺️ Routes & Route 🔗 Link 🎯 useParams 📦 react-router-dom 🕳️ rota 404
🚪
A dor: sua loja mora numa página só
E todo site de verdade tem VÁRIAS — cada uma com seu endereço

Abre qualquer site que você usa e repara na barra de endereço: cada tela tem um endereço próprio. Na loja de verdade seria assim:

  • meusite.com/ — a página inicial, com a vitrine;
  • meusite.com/sobre — quem somos;
  • meusite.com/produtos/2 — os detalhes do produto 2 (cada produto com o SEU endereço, que dá até pra mandar no WhatsApp!).

Já a sua Mini-loja… é localhost:5173 e acabou. 😅 Clicou, rolou, filtrou — o endereço não muda, e não existe "outra página" pra ir.

🤔 Peraí — o React não era "uma página só"?

Era e continua sendo! Lá no Cap 4 você aprendeu que um app React é uma SPA (Single Page Application): o navegador baixa UMA página, e o React vai trocando o que aparece dentro dela. O truque de hoje é fazer essa troca obedecer à barra de endereço: URL mudou → o React troca o componente — sem recarregar nada. Quem faz essa mágica é uma peça chamada React Router.

🏬 O shopping e o recepcionista

Pensa num shopping com um recepcionista na porta. Você chega e diz um destino ("loja de games", "praça de alimentação") e ele te aponta a área certa — sem você sair do prédio. O React Router é esse recepcionista: ele olha a URL (o destino) e decide qual componente entra em cena. O prédio (seu app) é um só; as "páginas" são áreas dele.

Agora o passo que liga o Router no app inteiro: no main.jsx (lembra dele? o plugue 🔌 do Cap 4), o BrowserRouter abraça o <App />:

src/main.jsxJSX
import { createRoot } from "react-dom/client"

import "./index.css"

createRoot(document.getElementById("root")).render(
  <BrowserRouter>

  </BrowserRouter>

🫂
Por que o abraço? O BrowserRouter é quem fica vigiando a barra de endereço. Tudo que estiver dentro do abraço ganha o poder de reagir à URL. Fora dele, nada de rotas — esquecer esse abraço é o Bug nº 1 do capítulo (o BugZilla te mostra o estrago).
🧪

Routes & Route — o mapa de páginas
Cada endereço aponta pra um componente. Simples assim.

Primeiro, as páginas precisam existir. Cada página é… um componente comum, igual aos que você faz desde o Cap 4! Só muda o costume: páginas moram numa pasta src/pages/:

src/pages/Sobre.jsx — uma página é só um componente (rafce!)JSX
const Sobre = () => {
  return (
    <div>
      <h2>Sobre a Mini-loja 👋</h2>
      <p>Feita em React, com dados de uma API de verdade.</p>
    </div>
  )
}

export default Sobre

Com as páginas criadas, o App.jsx vira o mapa: o <Routes> é o quadro de avisos do recepcionista, e cada <Route> é uma linha do quadro — "este endereço → este componente":

src/App.jsx — o mapa de rotasJSX
import { Routes, Route } from "react-router-dom"
import Home from "./pages/Home.jsx"
import Sobre from "./pages/Sobre.jsx"

const App = () => {
  return (
    <Routes>
      <Route path="/" element={<Home />} />
      <Route path="/sobre" element={<Sobre />} />
    </Routes>
  )
}

A anatomia de UMA linha do mapa — repara que é o mesmo espírito do useEffect(O QUE, QUANDO), só que em JSX:

<Route path="/sobre" element={<Sobre />} />
path → QUANDO: em qual endereço element → O QUE: qual componente entra em cena Route → uma linha do mapa

Brinca de recepcionista: escolha uma URL e veja qual linha do mapa bate (e o que aparece na tela) 👇

Link — navegar sem apertar F5
O botão de teletransporte da SPA

Digitar URL na mão funciona, mas usuário navega clicando. No HTML do Cap 1 você usaria um <a href="/sobre">… só que o <a> tem um "defeito" pra SPA: ele manda o navegador recarregar a página inteira — joga seu app fora, baixa tudo de novo, zera todos os estados. 💥

O Router traz o substituto certo: o <Link>. Por fora parece um <a> (até vira um <a> no HTML final!), mas por dentro ele só avisa o recepcionista: "troca pra /sobre" — e o React troca só o miolo, instantâneo:

o antes e o depoisJSX
// ❌ no site tradicional (recarrega TUDO):
<a href="/sobre">Sobre</a>

// ✅ na SPA (troca só o componente):
import { Link } from "react-router-dom"

<Link to="/sobre">Sobre</Link>
👀
Duas trocas pra decorar: a tag (a → Link, com L maiúsculo — é um componente!) e o atributo (href → to).

Sinta a diferença na pele: encha o carrinho e navegue dos dois jeitos 👇

Rota com :id — uma página, mil produtos
O pedaço variável da URL + useParams pra ler ele

Agora o pulo do gato do capítulo. A loja tem 4 produtos — e amanhã pode ter 400. Criar uma rota pra cada (/produtos/1, /produtos/2, …) seria loucura. A solução: UMA rota com um pedaço variável, marcado com dois-pontos:

src/App.jsx — a linha nova do mapaJSX
<Route path="/produtos/:id" element={<Detalhes />} />
🏨 O quarto de hotel

O hotel não constrói uma recepção por hóspede — tem UM corredor e portas numeradas. /produtos/:id é o corredor; o :id é a plaquinha do quarto, que muda a cada visita: /produtos/1, /produtos/2, /produtos/77… todas caem na MESMA rota, e a página Detalhes lê a plaquinha pra saber qual produto mostrar.

E como a página lê a plaquinha? Com um hook novo do Router — o useParams:

src/pages/Detalhes.jsx — lendo o :id da URLJSX
import { useParams } from "react-router-dom"

const Detalhes = () => {
  const { id } = useParams()   // na URL /produtos/2 → id vale "2"

  return <h2>Detalhes do produto {id}</h2>
}

Passeia pelos quartos e repara no que o useParams devolve 👇

URL:
const { id } = useParams() // a rota é /produtos/:id
…
🔤
Reparou nas aspas? O useParams devolve o id como TEXTO ("2", não 2) — tudo que vem de URL é texto. Pra montar a URL da API isso não atrapalha em nada; só não vá comparar com === contra um número.

Agora o gran finale: juntar o :id com o Cap 7 inteiro. O json-server já sabe responder um produto só — teste no navegador: localhost:3000/produtos/2 devolve só o Monitor! Então a página Detalhes é o padrão canônico com o id na URL:

src/pages/Detalhes.jsx — completa (Cap 7 + Cap 8 juntos ⭐)JSX
import { useState, useEffect } from "react"
import { useParams, Link } from "react-router-dom"
import axios from "axios"

const Detalhes = () => {
  const { id } = useParams()
  const [produto, setProduto] = useState(null)   // ainda não chegou

  useEffect(() => {
    axios.get("http://localhost:3000/produtos/" + id)
      .then((res) => setProduto(res.data))
  }, [id])   // modo 3 do Cap 7: se o id mudar, busca de novo!

  if (!produto) {
    return <p>⏳ Carregando...</p>   // porteiro na porta
  }

  return (
    <div>
      <Link to="/">← voltar pra loja</Link>
      <h2>{produto.nome}</h2>
      <p>R$ {produto.preco}</p>
    </div>
  )
}

export default Detalhes
🚪 O porteiro na porta (novidade pequena, honesta)

O produto começa null (a resposta ainda não chegou) — e null.nome quebraria a página. O if (!produto) { return ... } é só o if + return do Cap 2 usados na porta do componente: "se o dado ainda não chegou, devolve o ⏳ e nem continua". Quando o axios responder, o set dispara nova foto 📸 e aí sim o resto roda.

Falta o começo da viagem: transformar cada card da vitrine num Link pro seu próprio quarto. No CartaoProduto, o nome vira link (repare: o to é montado com o id, como a URL do axios):

src/CartaoProduto.jsx — o nome vira a porta de entradaJSX
import { Link } from "react-router-dom"

// no lugar do nome puro:
<Link to={"/produtos/" + id}>{nome}</Link>

A rota curinga — adeus, tela branca
O que aparece quando NENHUM endereço bate

Lá na máquina do recepcionista você viu: URL sem rota = tela branca. 😱 Site profissional tem resposta até pro endereço errado — a famosa página 404 ("não encontrei"). No Router, isso é uma rota com o curinga * no path:

src/App.jsx — a última linha do mapaJSX
<Routes>
  <Route path="/" element={<Home />} />
  <Route path="/sobre" element={<Sobre />} />
  <Route path="/produtos/:id" element={<Detalhes />} />
  <Route path="*" element={<NaoEncontrada />} />  // pega TODO o resto
</Routes>

O mesmo mapa de antes, agora com o curinga de plantão — repara que ele só entra quando ninguém mais bate 👇

BugZilla ataca as rotas!
Os 5 tropeços clássicos do React Router
🐛
Bug 1 — esqueceu o abraço do BrowserRouter: a tela explode com "useRoutes() may be used only in the context of a <Router>". Tradução: você usou Routes/Link, mas ninguém está vigiando a URL. Conserto: no main.jsx, o <BrowserRouter> abraçando o <App />.
🐛
Bug 2 — usou <a> em vez de <Link>: "funciona"… mas a cada clique a página pisca e recarrega, e todos os estados zeram (adeus, carrinho). Conserto: dentro do app, navegação é com <Link to="...">. O <a> fica pra links que SAEM do site.
🐛
Bug 3 — path escrito diferente do Link: Route com path="/Sobre" e Link com to="/sobre" (ou um typo tipo /produto/:id vs /produtos/2) → cai no 404 sem explicação. Conserto: os endereços têm que bater LETRA POR LETRA. Na dúvida, copie e cole.
🐛
Bug 4 — esqueceu o import: "Link is not defined", "Routes is not defined"… Conserto: tudo do Router vem do mesmo lugar, com chaves: import { Routes, Route, Link, useParams } from "react-router-dom" (cada arquivo importa só o que usa).
🐛
Bug 5 — comparar o id com número: id === 2 dá false mesmo na URL /produtos/2 — porque o useParams devolve "2" (texto!). Conserto: pra URL do axios, use o texto direto ("/produtos/" + id); se um dia precisar do número, converta com Number(id).
👀 Macete de ouro do BugZilla▼
🔦
Página não aparece? Investigue na ordem do caminho: 1) o BrowserRouter está abraçando o App no main.jsx? · 2) a URL na barra é EXATAMENTE o path do Route? · 3) o componente do element foi importado no App? · 4) o Link aponta pro mesmo endereço do path? Se os 4 passarem e a página de detalhes estiver vazia, o problema é o Cap 7 dela (json-server de pé? res.data? porteiro do null?).

src/pages/Detalhes.jsx — a versão de galaJSX
import { useState, useEffect } from "react"
import { useParams, Link } from "react-router-dom"
import axios from "axios"

const Detalhes = () => {
  const { id } = useParams()
  const [produto, setProduto] = useState(null)
  const [erro, setErro] = useState(false)

  useEffect(() => {
    axios.get("http://localhost:3000/produtos/" + id)
      .then((res) => setProduto(res.data))
      .catch(() => setErro(true))
  }, [id])

  if (erro) {
    return (
      <div>
        <p>😵 Não achei esse produto…</p>
        <Link to="/">← voltar pra loja</Link>
      </div>
    )
  }

  if (!produto) {
    return <p>⏳ Carregando...</p>
  }

  return (
    <div>
      <Link to="/">← voltar pra loja</Link>
      <h2>{produto.nome}</h2>
      <p>R$ {produto.preco}</p>
      <p>{produto.emEstoque ? "✅ em estoque" : "😢 esgotado"}</p>
    </div>
  )
}

export default Detalhes
🧠
Repara na ordem dos porteiros: primeiro o erro, depois o !produto (⏳), e só então a festa. O json-server responde "não achei" (status 404 — olha ele aí de novo!) pra id inexistente, e o axios manda direto pro .catch.

O que você leva deste capítulo
Sua SPA agora tem endereços — e continua sendo UMA página
  • React Router: npm install react-router-dom + o abraço do <BrowserRouter> no main.jsx — o vigia da barra de endereço.
  • O mapa: <Routes> com linhas <Route> — path = QUANDO (o endereço), element = O QUE (o componente). Páginas são componentes comuns, morando em src/pages/.
  • Navegar é com <Link to="..."> — troca só o miolo, instantâneo. <a href> dentro da SPA = reload + estados zerados.
  • Rota dinâmica: path="/produtos/:id" — uma rota, infinitos produtos. A página lê a plaquinha com const { id } = useParams() (vem como TEXTO!).
  • Detalhes = Cap 7 + Cap 8: useParams pega o id → axios busca /produtos/ + id → useState guarda → porteiros seguram o null. Tudo velho conhecido, só combinado.
  • Rota curinga *: a página 404 amigável que pega qualquer endereço perdido — com Link de volta.
