O que é HTML?
HyperText Markup Language — a planta da página
Pensa numa casa 🏠

O HTML é a estrutura bruta: as paredes, o telhado, as portas, os cômodos. Sem decoração nenhuma. É o que define o que existe na página: um título aqui, um parágrafo ali, uma imagem, um botão.

O CSS (que vem já já) é a decoração: a cor da parede, o piso, os móveis. E o JavaScript (próximo capítulo) é a parte elétrica: o que acontece quando você aperta o interruptor.

HTML é feito de tags. Uma tag é um rótulo entre < e > que diz ao navegador "isto aqui é um...". A maioria vem em par: uma de abertura e uma de fechamento (com uma barra /):

exemplo de uma tag HTML 
<p>Olá, eu sou um parágrafo!</p>
 ↑ abre                       ↑ fecha (tem a barra /)
🔤
"Markup" = marcação. Você não está programando lógica ainda — está marcando os pedaços do conteúdo: "isto é um título", "isto é uma lista".
🔬
A anatomia de uma tag
As peças que toda tag tem — e os nomes certos delas

Antes de sair escrevendo, bora olhar de pertinho uma tag. Pega um link como exemplo. Cada cor abaixo é uma peça com nome próprio:

<a href="https://google.com">Ir pro Google</a>
Tag de abertura <a> — diz "começa um link aqui".
Atributo href="..." — uma config no formato nome="valor".
Conteúdo — o que aparece na tela (o texto clicável).
Tag de fechamento </a> — a barra / diz "acabou o link".
📐 A fórmula que se repete sempre

É quase sempre o mesmo molde: <tag> conteúdo </tag>. Troque a palavra e você troca o "papel" daquele pedaço: <p> é parágrafo, <h1> é título, <button> é botão. Decora esse molde — 90% do HTML é isso.

🐛
As "solitárias" (void elements). Umas poucas tags não têm conteúdo nem fechamento — elas se viram sozinhas: <img> (imagem), <input> (campo) e <br> (quebra de linha). São a exceção; a maioria vem em par.

📌 As duas salas da casa

<body> = a sala de visitas: tudo que aparece na tela (textos, imagens, botões) fica aqui dentro.

Atributos são "configurações" dentro da tag de abertura, no formato nome="valor". Ex.: href (pra onde o link vai), src (de onde vem a imagem), alt (texto alternativo, importante pra acessibilidade!).
🐛
Tags "solitárias": <img>, <input> e <br> não têm tag de fechamento. São exceções — a maioria vem em par.
🪆
Tags dentro de tags (aninhamento)
Como uma página vira uma árvore — e por que a indentação importa
Bonecas russas 🪆

Tags vivem umas dentro das outras, como bonecas russas (ou caixas dentro de caixas). Um item de lista (<li>) fica dentro da lista (<ul>), que fica dentro do corpo (<body>). A regra de ouro: a última que abre é a primeira que fecha.

<body> <ul> <!-- abre a lista --> <li>Item um</li> <!-- li dentro de ul --> <li>Item dois</li> </ul> <!-- fecha a lista --> </body>
⌨️
Indentação = empurrar pra direita. Cada vez que você entra "uma caixa pra dentro", dê um Tab (ou 2 espaços). O HTML funciona sem isso, mas fica ilegível. Código alinhadinho é a diferença entre achar e não achar o erro depois. 🧹
🐛
Não "cruze" as tags. Isto está errado: <b><i>texto</b></i>. O certo é fechar na ordem inversa da abertura: <b><i>texto</i></b>. Última a abrir, primeira a fechar. 🔒

🌳 DOM = a árvore da página

DOM (Document Object Model) é só um nome chique pra "a página em forma de árvore": o <html> é o tronco, <body> é um galho, e cada tag é uma folhinha. Guarde esse nome — quando chegarmos no JavaScript e no React, a gente vai mexer nessa árvore o tempo todo. 🌳

🏠
HTML semântico — dando nome aos cômodos
Tags que dizem o "papel" de cada parte da página
Os cômodos da casa 🚪

Você poderia montar uma casa só com "espaços" genéricos. Mas faz muito mais sentido nomear: cozinha, quarto, sala. No HTML é igual: em vez de usar <div> pra tudo, usamos tags com significado (semântica):

pagina.htmlHTML
<header>   <!-- topo: logo, título -->
  <h1>Meu Site</h1>
</header>

<nav>      <!-- menu de navegação -->
  <a href="#">Início</a>
</nav>

<main>     <!-- conteúdo principal -->
  <section>
    <article>Um texto importante aqui.</article>
  </section>
</main>

<footer>   <!-- rodapé -->
  <p>© 2026 Meu Site</p>
</footer>
🎯
Por que isso importa? 1) Outros devs entendem seu código na hora. 2) O Google lê melhor seu site (SEO). 3) Leitores de tela (acessibilidade) ajudam pessoas cegas a navegar. É a marca de um dev profissional, não amador.

Tabelas e Formulários
Pra mostrar dados em grade e pra receber dados do usuário

Tabela — pra dados em linhas e colunas (tipo Excel):

tabela.htmlHTML
<table>
  <tr>                      <!-- tr = linha -->
    <th>Nome</th>           <!-- th = cabeçalho -->
    <th>Idade</th>
  </tr>
  <tr>
    <td>João</td>           <!-- td = célula -->
    <td>25</td>
  </tr>
</table>

Formulário — pra receber dados (login, cadastro). Toda telinha de login é isto:

login.htmlHTML
<form>
  <label>E-mail:</label>
  <input type="email" placeholder="voce@email.com">

  <label>Senha:</label>
  <input type="password">

  <button>Entrar</button>
</form>
💡 O atributo type do input

type="text" (texto), type="email" (e-mail), type="password" (esconde a senha com •••), type="number" (só números). O navegador já ajuda você de graça!

🎨
O que é CSS?
Cascading Style Sheets — as roupas da página
Lembra da casa? 🏠

HTML é a estrutura crua. CSS é a decoração: cor de fundo, tamanho das letras, espaçamentos, posição dos elementos. A mesma casa (HTML) pode ficar com mil aparências diferentes só trocando o CSS.

A regra de CSS tem sempre esta forma:

anatomia de uma regra CSS CSS 
h1 {                  /* seletor: QUEM vai ser estilizado */
  color: #2965f1;      /* propriedade: cor do texto */
  font-size: 32px;    /* propriedade: tamanho da fonte */
}

E como conectar o CSS no HTML? O jeito profissional é um arquivo .css separado, ligado no <head>:

index.html (dentro do head) HTML 
<link rel="stylesheet" href="estilo.css">
🗂️
Por que arquivo separado? Organização. O HTML cuida do conteúdo, o CSS cuida da aparência. Em projetos React (lá na frente) a gente vai além disso com CSS Modules.
🎯
Seletores: mirando os elementos certos
Por tag, por classe, por id
estilo.css CSS 
/* por TAG: todos os parágrafos */
p { color: gray; }

/* por CLASSE: elementos com class="destaque" (começa com .) */
.destaque { background: yellow; }

/* por ID: o elemento com id="topo" (começa com #) */
#topo { font-size: 40px; }

No HTML, você "marca" os elementos com class e id:

index.html HTML 
<h1 id="topo">Bem-vindo</h1>
<p class="destaque">Esse parágrafo fica com fundo amarelo</p>
💡 Classe x Id

Classe (.) pode repetir em vários elementos — use à vontade. Id (#) deve ser único na página. No dia a dia, classe é o que você mais vai usar.

Propriedades que você vai usar o tempo todo:

propriedades comuns CSS 
.cartao {
  color: #222;            /* cor do texto */
  background: #f4f4f4;     /* cor de fundo */
  font-size: 16px;       /* tamanho da fonte */
  padding: 20px;          /* espaço INTERNO */
  margin: 10px;           /* espaço EXTERNO */
  border-radius: 12px;    /* cantos arredondados */
}
📦
Box model: tudo é uma caixa
A confusão #1 de quem começa — vamos matar ela agora
📦 Um quadro na parede

Imagine um quadro: a foto é o conteúdo. O passe-partout (aquela borda branca por dentro) é o padding. A moldura é o border. E o espaço até o próximo quadro na parede é o margin.

margin (fora)
border
padding (dentro)
content
🎯
Macete: padding empurra o conteúdo pra dentro da caixa. margin empurra a caixa pra longe das outras. Confundir os dois é normal — olha esse desenho sempre que travar.
🧰
Flexbox & o lendário "centralizar a div"
O meme mais real da história do frontend

Durante anos, centralizar uma caixinha no meio da tela foi um pesadelo. Hoje temos o Flexbox — e a brincadeira virou 3 linhas. Você coloca display: flex no elemento-pai (o container) e ele passa a organizar os filhos pra você:

estilo.css CSS 
.container {
  display: flex;            /* liga o flexbox */
  justify-content: center;  /* centraliza na horizontal ↔ */
  align-items: center;      /* centraliza na vertical ↕ */
  height: 150px;
}

Resultado (esse quadrado está centralizado com exatamente esse CSS):

🎯
🧭 Decora essa dupla

justify-content = eixo principal (horizontal, por padrão). align-items = eixo cruzado (vertical, por padrão). Os dois em center = coisa centralizada. Esse é o feijão com arroz de 90% dos layouts.

BugZilla ataca!
Os erros clássicos de HTML/CSS — e como derrotar
🐛
Bug 1 — tag não fechada. Você abre <p> mas esquece o </p>. A página "vaza" e tudo abaixo fica estranho.
👀 Ver o conserto▼
corrigidoHTML
<!-- ERRADO -->
<p>Olá

<!-- CERTO: sempre feche a tag -->
<p>Olá</p>
🐛
Bug 2 — CSS não aparece. Você escreveu o CSS lindo, salvou, e... nada mudou. Na maioria das vezes é o <link> errado ou o nome do arquivo trocado.
👀 Ver o que checar▼
✅
1) O <link rel="stylesheet" href="estilo.css"> está no <head>? 2) O nome no href é idêntico ao do arquivo (maiúsculas contam!)? 3) O arquivo está na mesma pasta? 4) Você salvou (Ctrl/Cmd+S)?
🐛
Bug 3 — esqueceu o ; no CSS. Cada propriedade termina com ponto e vírgula. Esquecer um faz a propriedade seguinte ser ignorada silenciosamente.

Desafio Individual — cartao.html
Um cartãozinho de produto centralizado
💡 Dica pra fazer sozinho(a)

Crie cartao.html e estilo.css. No HTML, faça uma <div class="cartao"> contendo um <h2> (nome do produto), um <p> (preço) e um <button> (Comprar).

No CSS: dê background, padding e border-radius ao .cartao. Depois, no <body>, use flexbox pra centralizar o cartão na tela (lembra do justify-content + align-items?).

🚨

cartao.htmlHTML
<!DOCTYPE html>
<html lang="pt-BR">
  <head>
    <meta charset="UTF-8">
    <title>Cartão</title>
    <link rel="stylesheet" href="estilo.css">
  </head>
  <body>
    <div class="cartao">
      <h2>Tênis de Corrida</h2>
      <p>R$ 299,90</p>
      <button>Comprar</button>
    </div>
  </body>
</html>
estilo.cssCSS
body {
  display: flex;
  justify-content: center;
  align-items: center;
  height: 100vh;   /* vh = altura da tela toda */
  background: #f0f0f0;
}
.cartao {
  background: white;
  padding: 24px;
  border-radius: 14px;
  text-align: center;
  box-shadow: 0 4px 14px rgba(0,0,0,0.1);
}
.cartao button {
  background: #2965f1;
  color: white;
  border: none;
  padding: 10px 20px;
  border-radius: 8px;
  cursor: pointer;
}

O que você leva deste capítulo
Fixou? Então bora pro próximo
  • HTML é a estrutura: tags em par (<p>...</p>), o esqueleto html → head → body.
  • Tags essenciais: h1–h6, p, a, img, ul/li, button, input.
  • CSS é a aparência: seletor { propriedade: valor; }, conectado com <link>.
  • Seletores: tag, .classe, #id. Classe é a estrela.
  • Box model: content → padding → border → margin.
  • Flexbox: display:flex + justify-content + align-items = centralizou.
